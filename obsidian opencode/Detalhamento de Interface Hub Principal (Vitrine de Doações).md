**Objetivo da IA:** A estrutura visual desta interface já está definida. Sua tarefa é gerar **exclusivamente o script TypeScript (`.ts`) do componente Angular (`HubComponent`)**. Este componente é o centro do marketplace e deve focar na listagem de itens disponíveis e na lógica de solicitação, garantindo máxima organização e ausência de erros. 

## 1. Gerenciamento de Estado * Crie uma propriedade tipada para armazenar a lista de itens recebidos da API (ex: `doacoesDisponiveis: ItemDoacao[] = []`). * Implemente variáveis de controle de interface, como `isLoading: boolean` e `mensagemErro: string`, para controlar o *feedback* visual durante as chamadas HTTP. 

## 2. Inicialização e Integração (DoacaoService) * Injete o `DoacaoService` e o `AuthService` no construtor. * Utilize o ciclo de vida `ngOnInit()` para invocar o método do serviço que busca a lista de doações ativas. * **Regra Crítica de Negócio (Filtro):** O componente deve extrair o ID do usuário logado (via `AuthService`) e garantir que a lista de doações exibida **NÃO** inclua itens onde o `id_doador` seja igual ao ID do usuário atual. (O usuário não pode visualizar ou solicitar a própria doação). 

## 3. Lógica de Solicitação (Ação Principal) * Implemente o método `solicitarItem(idItem: number)`. * O fluxo de execução deve seguir esta ordem: 1. Chamar o endpoint de solicitação via `DoacaoService`. 2. Em caso de resposta bem-sucedida, remover o item solicitado do array `doacoesDisponiveis` localmente. Isso atualiza a interface instantaneamente sem necessitar de um novo "refresh" (re-fetch) na API. 3. Exibir um aviso de sucesso. 4. Tratar possíveis erros da API (como o item ter acabado de ser doado para outra pessoa) e atualizar a `mensagemErro`. 

## 4. Aplicação Estrita de Object Calisthenics Para manter o padrão do back-end em Java, o TypeScript do Angular deve respeitar estas regras: * **Proibição Absoluta do `else`:** Use o padrão *Early Return* (retorno antecipado). Se houver um erro na busca de itens ou na validação da solicitação, retorne e encerre o método imediatamente, deixando o fluxo de sucesso sempre no nível raiz da função. * **Apenas um nível de indentação por método:** Mantenha os métodos enxutos. Se o filtro que remove os itens do próprio usuário for complexo, isole essa lógica extraindo-a para um método privado (ex: `private removerItensProprios(itens: ItemDoacao[])`). * **Tipagem Forte:** É proibido o uso do tipo `any`.
