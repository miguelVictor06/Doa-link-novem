**Objetivo da IA:** 

O código HTML e CSS desta interface já foi construído. Sua tarefa é gerar **exclusivamente o script TypeScript (`.ts`) do componente Angular**, implementando a lógica de dupla função e a integração com os serviços, garantindo que não haja erros de compilação ou de lógica.
## 1. Gerenciamento de Estado (Toggle Mode) * A tela unifica Login e Cadastro. Crie uma variável de controle de estado (por exemplo, `isLoginMode: boolean = true` como padrão) para gerenciar qual visualização está ativa. * Crie um método limpo (ex: `alternarModo()`) para inverter esse estado. O HTML usará essa variável para renderizar dinamicamente os campos adicionais de cadastro (como Nome e Endereço) ou ocultá-los no modo Login. 

## 2. Gerenciamento de Dados e Validação (Reactive Forms) * Utilize **Reactive Forms** (`FormGroup`, `FormBuilder`, `Validators`) para garantir uma validação robusta e orientada a código, sem poluir o HTML. * **Regras de Validação:** * *Email:* Campo obrigatório e deve ter formato válido de e-mail. * *Senha:* Campo obrigatório, tamanho mínimo de 6 caracteres. * *Nome / Endereço:* Campos obrigatórios apenas quando o sistema estiver no modo Cadastro. (Dica para a IA: atualize a validação dos controles dinamicamente ao alternar o modo, ou trate isso na submissão). 

## 3. Submissão e Integração (AuthService) * Injete o serviço de autenticação (`AuthService`) e o serviço de rotas (`Router`) no construtor. * Crie o método `onSubmit()`. O fluxo deve ser: 1. Verificar se o formulário é válido. 2. Extrair os dados do formulário. 3. Verificar o estado de `isLoginMode` para decidir qual método do `AuthService` chamar (`login(dados)` ou `cadastrar(dados)`). 4. Em caso de sucesso na requisição HTTP, redirecionar o usuário para a rota `'/hub'`. 5. Em caso de erro, exibir uma mensagem no console ou variável de erro. 

## 4. Aplicação Estrita de Object Calisthenics Para manter o padrão do protótipo, o script gerado deve respeitar as seguintes regras: * **Não utilize a palavra `else`** sob nenhuma hipótese. Se o formulário for inválido no `onSubmit()`, use a técnica de "Early Return" (retorno antecipado). Em vez de `if/else` para separar a chamada de login ou cadastro, retorne cedo ou separe a responsabilidade em métodos menores. * **Apenas um nível de indentação por método.** Se a lógica de montagem do payload ou tratamento de erro ficar complexa, extraia-a para métodos privados auxiliares (ex: `private processarLogin()`, `private processarCadastro()`).
